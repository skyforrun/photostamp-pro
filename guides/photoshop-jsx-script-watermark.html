The anatomy of a Photoshop watermark script (JSX)

A watermark script is four parts: a small UI that collects settings, a loop over files, a stamping routine that works on one document, and error handling so one bad file does not end the run.

ExtendScript is old JavaScript, not modern JS. No arrow functions, no template literals, no let/const in older builds — write ES3-compatible code and it will run everywhere.

1. Collect settings first

Use a ScriptUI dialog to gather the logo path, output folder, opacity, position, and an on/off for the date. Ask once, before touching any file.

2. Loop the folder, not the open documents

Folder.getFiles with an extension filter gives you the list. Loop it, open each file, stamp, save a copy, close without saving the original.

3. Wrap each file in try/catch

A corrupt file or a locked one should not abort the batch. Catch per file, log the name and message, continue.

4. Write to a separate output folder

Never Save As over the input path. Derive an output name with a suffix and create the folder if missing.

5. Write a log

A plain text log in the output folder is the difference between "the batch worked" and knowing which three files failed.

Questions

Where do scripts go?

Anywhere — File > Scripts > Browse. To add a menu entry, copy it into Presets/Scripts.

Does it work on Mac and Windows?

Yes, as long as paths are built with Folder/File objects rather than string concatenation.

Can I sell a script I wrote?

Yes. A single-file tool has no runtime dependency, which makes distribution trivial.
