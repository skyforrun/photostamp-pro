Stamp the date on a batch of photos

Date stamps are the one watermark where the correct value changes per file. That single fact is why most batch workflows get it wrong and print today's date onto 500 archival scans.

For legal or insurance use, add the date inside the image rather than only in the filename — filenames are edited far more casually than pixels.

1. Understand the two date sources

Today's date is a constant, so an action can do it. The photo's EXIF capture date varies per file, and only something that reads metadata at run time can use it.

2. Check whether your files even have EXIF

Scans, screenshots, and exports that went through some pipelines strip it. Verify on a sample before planning a folder-wide run.

3. Pick a format that sorts correctly

yyyy-mm-dd sorts chronologically as text; dd/mm/yyyy does not. If the stamp doubles as an archive label, the sortable form wins.

4. Place it where it will not fight the subject

Bottom-centre is conventional for documentary work and insurance records; bottom-right collides with many logo marks.

5. Run it over a copy

Date stamps are the one mark people later want removed. Keep the source folder pristine.

Questions

Can Batch use each file EXIF date?

No. Batch replays a fixed action; the date text would be identical on every image.

What if EXIF is missing?

Fall back to file creation date or leave the stamp off for those files and log them.

Does the font matter?

Use a plain sans-serif at small size. Decorative fonts become unreadable at 2% of image height.
