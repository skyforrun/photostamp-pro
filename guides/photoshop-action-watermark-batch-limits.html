Why batch actions stop working for watermarks

An action is a recording. It replays exactly what you did, including the file you happened to have open. That is fine for a fixed pipeline and useless the moment the stamp needs a parameter.

The dividing line is simple: constant pipeline, use an action; variable stamp, use something that takes parameters.

1. The logo path is baked in

The action records the file you placed. Change studios, change logos, or move the file and the action breaks. There is no field to type a new path into.

2. Opacity and corner are constants

Recording "opacity 55%, bottom-right" means every run is 55% bottom-right. A client who wants a discreet top-left mark means re-recording, and every re-record is a chance to record the wrong thing.

3. EXIF dates cannot be read into text

An action can insert a text layer, but the text is whatever you typed. Per-photo capture dates require reading document metadata at run time — which actions cannot do.

4. Dialogs break the batch silently

Any step that opens a prompt — including some Save As and Export As configurations — either pauses the batch or fails per file. The run finishes, the folder is empty, and nothing tells you why.

5. Where actions still win

If your pipeline is truly constant — same canvas size, same logo, same corner, every delivery — an action plus Batch is free and fast. Do not replace it just to be modern.

Questions

Can I add a parameter to an action?

Not without a script. Actions have no input fields.

Do droplets solve this?

No — a droplet is an action with an icon. Same constants.

Is ExtendScript still supported?

Yes. It is the automation layer behind Batch and actions, and it ships inside current Photoshop builds.
